## 一、项目背景

### 1.1 数据来源

本工具的地图数据由 RTAB-Map 0.23.4 产出的 `.db` 数据库文件提供，具体字段含义与已验证的数据样本如下。

#### 已验证数据库：`underGround_split1.db`

| 字段 | 内容 |
|------|------|
| 数据库版本 | RTAB-Map 0.23.4 |
| 创建时间 | 2026-05-16 09:08:37 |
| 建图时长 | 约 7.4 分钟（09:08:37 → 09:16:04） |
| 场景类型 | 地下空间（矿井 / 管道） |

#### 数据库表结构

| 表名 | 行数 | 说明 |
|------|------|------|
| Node | 402 | 位姿节点，ID 1~431（非连续） |
| Data | 402 | 传感器数据（128 条纯激光 + 274 条含栅格） |
| Link | 402 | 节点间约束（401 邻接 + 1 回环） |
| Statistics | 431 | 统计记录（含 29 个已被剔除的关键帧） |
| Admin | 1 | 全局优化栅格地图（17583 字节，CV_8SC1） |
| Info | 1 | 运行参数配置 |
| Feature / Word / GlobalDescriptor | 0 | 未启用视觉特征 |

#### 关键数据特性

- **传感器类型**：仅激光雷达（无 RGB / 深度图）
- **栅格分辨率**：0.05 m/cell
- **地图原点**：(-3.34, -85.93)，坐标系原点 (0,0,0)
- **回环闭合**：1 处局部空间回环（`kLocalSpaceClosure`）

#### 地下场景专项传感器配置

| 参数 | 值 | 说明 |
|------|----|------|
| Grid/MaxGroundHeight | 0.15 m | 地面检测上限 |
| Grid/MinGroundHeight | -0.3 m | 地面检测下限 |
| Grid/NormalsSegmentation | true | 法向量分割启用 |
| Grid/RangeMax | 0（不限） | 激光最大距离不限制 |

## 二、需求概述

本工具面向地下 SLAM 建图场景，提供以下核心能力：

1. 从 RTAB-Map `.db` 文件导入轨迹数据，直接提取内置 2D 占用栅格地图作为底图显示
2. 支持轨迹播放回放，可在播放过程中或暂停时手动标注语义节点
3. 构建可编辑的拓扑地图（节点 + 边），支持节点/边删除、双向边、恢复出厂，并持久化保存
4. 基于拓扑地图执行 Dijkstra 最短路径规划，规划路径沿边插值生成密集轨迹
5. 以 UDP 协议实时发送插值后的路径轨迹，供外部导航系统消费
6. 提供独立 UDP 接收端脚本，实时接收、展示并保存路径数据
7. 可在 Windows / Ubuntu 运行，性能上兼容 Jetson 等嵌入式平台

| F-10.10 | 日志规范 | 启动 / 单图完成 / yes 添加 / yes 合并 / 单图失败 / 完成汇总，分别使用 warn / info / warn / info / error / warn 级别（详见 §六附录） |

### 5.2 地图底图来源

2D 底图直接从 `.db` 的 Admin 表提取，无需额外生成：

```python
import sqlite3, numpy as np, cv2
conn = sqlite3.connect('underGround_split1.db')
row = conn.execute("SELECT opt_map FROM Admin").fetchone()
buf = np.frombuffer(row[0], dtype=np.uint8)
img = cv2.imdecode(buf, cv2.IMREAD_UNCHANGED)
# img: CV_8SC1，-1=未知，0=空地，100=障碍物
```

### 5.3 坐标系转换

```python
origin_x, origin_y, resolution = -3.34, -85.93, 0.05

def world_to_pixel(wx, wy, map_height):
    px = int((wx - origin_x) / resolution)
    py = map_height - int((wy - origin_y) / resolution)
    return px, py
```

**UDP 接收端输出**（`tools/udp_receiver.py`）

接收到的路径保存为两个文件：

`path_YYYYMMDD_HHMMSS.json` — 结构化数据：
```json
{
  "metadata": {
    "source_ip": "0.0.0.0",
    "source_port": 14550,
    "received_at": "2026-05-29T12:00:00",
    "point_count": 150,
    "total_length_m": 12.345,
    "time_span_s": 7.450
  },
  "path": [
    {"seq": 0, "x": 1.23, "y": 4.56, "yaw": 0.52, "timestamp": 1778851588.59},
    ...
  ]
}
```

`path_YYYYMMDD_HHMMSS.csv` — 表格数据：
```
seq,x,y,yaw,timestamp
0,1.2300,4.5600,0.5236,1778851588.590
1,1.2500,4.5700,0.5236,1778851588.690
```

**抽帧图像输出**（`datasets/pic/`，由「处理数据」按钮生成）

文件名格式（**v0.5 修订**）：`{idx:04d}_t{timestamp:.3f}_x{+x:.4f}_y{+y:.4f}.jpg`

示例：

```
0001_t1778851623.092_x+0.8461_y-2.0429.jpg
0002_t1778851635.693_x+1.1297_y-6.6648.jpg
0003_t1778851654.592_x+1.5029_y-13.8242.jpg
```

字段含义：

| 段 | 含义 |
|----|------|
| `NNNN` | 1-based 4 位 0 填充的序号，按轨迹时间戳升序分配；保证文件系统字母序 = 时间戳序 |
| `t` | 节点 `timestamp_unix`（3 位小数），auto_node 凭此反查 db_nodes 取 z/yaw |
| `x` | 对应轨迹节点的世界坐标 X（米，4 位小数，含正负号） |
| `y` | 对应轨迹节点的世界坐标 Y（米，4 位小数，含正负号） |
| 编码 | JPEG |
| 分辨率 | 720p（高度固定 720，宽度按源视频宽高比缩放） |

**变更原因**：v0.4 命名 `x..._y..._t....jpg` 把 x 放最前，文件系统字母排序时按 x 值排（轨迹回环导致 x 非单调），用户肉眼浏览顺序混乱。v0.5 改用序号前缀后，文件管理器默认排序即时间顺序。

## 十一、Pure Pursuit 轨迹控制（F-11.x）

> **版本**：v0.4（2026-06-10）  
> **背景**：在路径规划完成后，增加基于 Pure Pursuit 算法的实时轨迹跟踪控制模块，将转弯半径 R 和速度 v 通过 UDP 发送给底盘控制器，同时在 UI 右侧面板提供在线调参能力。

---

### 11.1 算法功能需求

| 编号 | 功能 | 说明 |
|------|------|------|
| F-11.1 | 动态预瞄半径 | 以车辆当前位置为圆心，动态半径 `r ∈ [r_min, r_max]` 画圆；`r` 由局部轨迹曲率线性映射：曲率越大 r 越小，直行时 r = r_max |
| F-11.2 | 预瞄点查找 | 从当前最近轨迹点向前遍历，取第一个距车辆距离 ≥ r 的轨迹点作为预瞄点 |
| F-11.3 | 转弯半径 R 计算 | Pure Pursuit 公式：`R = -r×1000 / (2×sin(δ))`，单位 mm；δ = 预瞄方向角 - 当前 yaw，归一化到 [−π, π]；R > 0 右转，R < 0 左转，\|R\| ≥ 10000 截断为 10000（直行） |
| F-11.4 | 速度 v 计算 | `\|δ\| < δ_thresh` → `v = v_straight`；`\|δ\| ≥ δ_thresh` → `v = v_turn`；单位 mm/s |
| F-11.5 | UDP 发送格式修改 | 每帧发送 **16 字节 binary**：`struct.pack('>dd', R, v)`，替换原 JSON 格式；端口保持 `settings.json` 中配置值不变 |
| F-11.6 | CSV 轨迹文件扩展 | 新生成的 `received_paths/path_*.csv` 在原有 `seq, x, y, yaw, timestamp` 基础上新增两列：`speed`（mm/s）和 `radius`（mm）；历史 CSV 文件不修改 |

### 12.6 操作模式 — 路径规划逻辑（F-12.6）

| 编号 | 功能 | 说明 |


- `pic_playback_speed`：上次选择的倍速档位，启动时回填悬浮窗倍速选择器
- `pic_overlay_geometry`：悬浮窗上次的 `[x, y, width, height]`，关闭程序前自动保存，重新打开时还原位置与大小（若超出当前屏幕分辨率范围则回退默认位置）

### 13.5 验收标准

| 编号 | 检查项 | 期望 |
|------|--------|------|
| F-13.1 | 播放联动唤醒 | 按 Z 或点击播放按钮，悬浮窗与轨迹播放同时启动 |

| F-14.3 | 图片来源回退 | 节点无对应 `auto_node` 结果图时正确回退原图，不报错也不显示空白 |
